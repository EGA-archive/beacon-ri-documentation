Beacon Template UI
UI Deployment
1. Prerequisites
Docker
Make sure Docker and Docker Compose are installed on your machine.
You can verify this by opening up the terminal on your computer and input the following:
docker --version
docker compose version
You should expect both commands printing a version, for example:
Docker version 27.3.1, build ce12230
Docker Compose version v2.29.7-desktop.1
Code Editor
You will need a code editor (e.g. Visual Studio Code) to:
Edit the config.json (located at: client/public/config/config.json)

2. Clone the repository
Open your terminal and navigate to the folder where you want to store the project (for example, your Desktop):

cd Desktop

Then, clone the Beacon Template UI repository:

git clone https://github.com/EGA-archive/beacon-template-ui.git

Once the cloning process finishes, you can open the app inside your code editor, and then go inside the project directory:

cd beacon-template-ui
This means you’re in the correct directory and ready to start editing the configuration.

3. Edit and Customize the Beacon Template UI
Before starting the application, review the Configuration File section and verify the following:

 Configure client/public/config/config.json for your Beacon deployment.
 Verify that all configured logos and image assets are accessible.
Local assets can be placed in client/public/assets/logos/ , or image fields can reference external HTTP/HTTPS URLs.
Check the favicon, main logo, founder logos, About page logos, and funding organization logos where configured. SVG is recommended but not mandatory.

4. Start the application with Docker
In your terminal run:
docker compose up -d --build
Docker will automatically build the image and start the UI container.

5. Verify the Container
To confirm that the application container is running, execute the following command:

docker ps
Look for a running container named template-ui. The output should be similar to:

CONTAINER ID   IMAGE                              COMMAND                  STATUS          PORTS                    NAMES
123abc456def   beacon-template-ui-client:latest   "/docker-entrypoint..."   Up 10 seconds   0.0.0.0:3000->80/tcp     template-ui

Container details may vary depending on the environment. Once the container is running, open http://localhost:3000 to verify that the application loads correctly.

6. Stop or Restart the Application
To stop the application and remove its Docker container, run the following command from the project directory:

docker compose down
To start the application again, or rebuild it after modifying the frontend source code or bundled assets, run:

docker compose up -d --build
Changes to client/public/config/config.json do not require rebuilding or restarting the container. Reload the application in your browser to apply the updated configuration.

Updating to a New Beacon Template UI Version
The runtime config.json can be reused across releases, provided it remains compatible with the new version's validation schema.

To update the Beacon Template UI:

Back up your configuration
Save a copy of client/public/config/config.json and any customized assets.

Update the source code
Pull the latest changes from the repository or check out the desired release. Compare your configuration with the new config.example.json and validation schema, updating it if necessary.

Rebuild and restart the application
Run the following command from the project directory:

docker compose up -d --build

Note:
Changes to frontend source code or bundled assets require rebuilding the Docker image.

Changes to config.json do not require a rebuild when the runtime configuration directory is mounted as described in this guide. Reload the application to apply the updated settings.
